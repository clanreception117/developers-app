## NOT verified (honest limits)
1. **Real Google Colab run.** I tested on a Linux sandbox with Node 22, not on Colab itself. The Node-install step (NodeSource, only if Node < 18.17) was not exercised.
2. **Cloudflare tunnel / public URL.** The sandbox blocks `trycloudflare.com`. The `cloudflared` binary downloaded and ran (v2026.11.1), but no tunnel was created, so no public URL was produced or tested.
3. **GitHub publication and Colab link.** No GitHub credentials, so nothing was published. `USERNAME/REPOSITORY` placeholders remain until you run `publish.sh`.
4. **Browser-side behavior.** Buttons, framer-motion animations, scroll-driven animation, audio atmosphere and confetti are client-side and were not exercised in a real browser; only server responses were tested.
5. **Original localhost comparison.** Not done side by side; the original ran only as served from the package copy.

## Known behavior differences / findings
- `WelcomeStage.tsx` shows its "Dev-Only Evaluation Mode" only when `window.location.hostname` is `localhost` or `127.0.0.1`. Over the tunnel URL that panel will be hidden. This is original design; I did not edit it.
- The notebook runs the production server (`next start`) instead of `next dev` for stability and speed.
- API data (`/api/*`) is in-memory per server process and resets when the notebook restarts; same as localhost.
- `npm` reports `next@14.2.18` as deprecated with a known security vulnerability. Versions were kept exact as requested; consider upgrading Next.js separately.
- `supabase/migrations/*.sql` is not referenced by any code; it is included but unused.
- The tunnel URL is public to anyone with the link while the notebook runs. No secrets exist in the project or notebook output.
